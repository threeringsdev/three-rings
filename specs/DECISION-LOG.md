- 2026-07-16: **catalog-search spec reviewed + accepted — flat term grammar, substring SQL, name-order keyset.** V1 syntax = flat AND-of-terms (bare/name, `o:`, `t:`, `s:`, `r:`, `c:`, `id:`, `mv:` with comparisons), per-term `-` negation, and a **comma-OR micro-extension** (`r:rare,mythic`) — it's what the rail's multi-select facets serialize to, since flat Scryfall syntax can't express within-facet OR; no `or`/parens (real grammar, deferred). **Substring semantics everywhere** via trgm ILIKE; a generated `cards.oracle_search_text` column (+ GIN) closes data-model's multi-face `o:` gap; `t:` gets a type_line trgm GIN; `c:` handles multi-face via jsonb containment on `card_faces` (top-level colors is empty on DFCs by design). **Printing-scoped terms (`s:`/`r:`) share one EXISTS** (Scryfall's per-printing semantics); negated ones get their own NOT EXISTS. **Unknown syntax errors, naming the term** (never silently-wrong results); the "N advanced terms" rail indicator is dropped for v1. **Order = (name, oracle_id)** — Scryfall's own default and the shell's existing keyset — correcting collection-api's "relevance, then name" line (note added there); relevance deferred to an `order:`/tsvector extension. Reviewed and implemented **stacked on the ingestion-POC branch** (maintainer: rebase-merge, both PRs ride together) so the engine develops against the live dev subset.
- 2026-07-16: **catalog-ingestion spec reviewed + accepted — manifest-driven dailies, bulk for bootstrap/true-up, Render cron.** Facts verified live against Scryfall/Neon/Render docs and APIs (recorded in the spec): bulk files are now gzipped JSONL (streamable line-by-line); the `*.scryfall.io` bulk origins are rate-limit-free; every `api.scryfall.com` call needs an accurate `User-Agent` (403 without); upstream prices change once/day, period. Design: **two acquisition paths over one shared core** — the `default_cards` bulk path (POC filter → full bootstrap → occasional *manual* true-up that also refreshes all prices; hash-gated upserts so true-ups write only deltas) and the **daily incremental** (`/cards/manifest` sweep, 15,000 entries/page ≈ 8 pages ≈ 1 min → hydrate changed/new ids via `/cards/collection` 75/req → same upserts; new-card detection = unknown ids, the daily payoff). **Price freshness is an explicit non-goal** (maintainer): prices ride hydration + true-up cadence; no daily all-cards price job, and no daily 560 MB reprocessing. **Scheduling = a Render cron job** (~$1/mo minimum, at-most-one-run guaranteed, same root `Dockerfile`, command `server --ingest update`; the `catalog_ingest` credential lives *only* there — the web service keeps `app_runtime` only). Chosen over the same-day pg_cron due-marker idea (verified: no `http`/`pg_net` on Neon, ticks fire only while the compute is awake → usage-proportional freshness) and over GitHub Actions (standing no-DB-creds-in-GitHub rule). Scryfall `/migrations` reconciled catalog-side only (`merge`/`delete` iff unreferenced); user-row repointing is a manual owner runbook (RLS-forced tables; Neon can't mint `BYPASSRLS`). Manifest observation 2026-07-16: `data_updated_at`/`created_at`/`oracle_id` NULL on all sampled entries (maintainer's read: NULL is the steady state — cards rarely change); the diff reads them whenever present. New ingestion-owned migration queued with the work: `ingestion_runs`, `ingest_hash` + `manifest_*_updated_at` columns, `catalog_ingest` grants.

- 2026-07-16: **Data-access trait layer implemented; `ssr` decomposed into a substrate + two backends.** The `app` crate's `ssr` feature no longer *implies* Postgres. It is now the embedded-server **substrate** (router + auth core); a complete server build layers on exactly one **backend** — `hosted` (sqlx against Neon, the authorization terminus; what `server` builds) or `native` (an HTTPS client of the hosted API, **no sqlx linked**; what `src-tauri` builds), each implying `ssr`, with a `compile_error!` if neither is set.
